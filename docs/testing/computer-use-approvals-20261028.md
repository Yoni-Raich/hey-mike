## Change

- Route empty MCP confirmation forms to the existing per-chat approval card.
- Return `accept`/`decline` with the correct content only after a real user
  answer. No persistent app grant or configuration change.
- Show the plugin and original request, with request-only consent.
- Consume answers atomically; revoke the matching card and token when the
  server resolves it. Keep request IDs scoped to the owning computer/chat.
- Decline forms needing values, URL flows, verification challenges, unknown
  schema constraints or missing thread/turn scope. Full form UI is out of scope.
